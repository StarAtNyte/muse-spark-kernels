# Humming long-prefill grouped GEMMs with compiled SwiGLU

The prior `humming_prefill_long_grouped_v1` diagnostic measured a large standalone PyTorch SwiGLU sequence between Humming GEMMs. Humming exposes `ops.process_input` with `binary_split` activation, so this follow-up replaces that sequence with one compiled elementwise kernel implementing `a/(1+exp(-a))*b`. This is an activation kernel between GEMMs, not a GEMM-fused epilogue. Inputs and output remain BF16; no activation quantization is introduced.

The experiment uses the exact current best prefill source and the same synthetic 23,497-route distribution, expert weights, pre-gathered normalized inputs and H200 public image as the earlier diagnostic. It compares Humming output with the parent expert rows, times both complete components and individually flushed stages with eight graph replays, and retains raw output in `modal.log`. Humming excludes routing/gather/normalization while the parent includes gather and plan; this is an advantageous diagnostic, not an integrated submission or official score. Separate captures are not additive bounds. The subprocess is capped at 300 seconds.

Run `ap-qYfuhR4h3VJ638osvrjPeK` completed with return code 0. The output was finite and 0.00410 relative L2 from the parent expert rows. The parent including gather/plan measured 3001.20 µs; pre-gathered Humming measured 3467.22 µs. The standalone activation stage measured 139.79 µs versus 1266.93 µs for the prior Torch sequence (separate runs, same diagnostic shape); GEMM stage medians were 2487.70 and 1249.23 µs, with substantial GEMM1 variation. The improved Humming path is still about 15.5% slower than the parent in this diagnostic. Separate stage measurements are not additive bounds and the result does not rule out schedule tuning or a fused design. No candidate is promoted or submitted.
