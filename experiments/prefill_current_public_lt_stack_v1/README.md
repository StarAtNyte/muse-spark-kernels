# Public cuBLASLt heuristic pins on current prefill

The public `ruwwww/open-kernel-challenge` commit `c035bf9d5a7d2445d8c8ee5ce49e63b8bb36f49d` pins more cuBLASLt heuristic signatures than our current best prefill source (SHA-256 `f1807a75ec056b7f3874d4fce02331ca0043ac38a45af7710a8287a252421a92`). This experiment applies the public signatures as runtime plan selections to our existing implementation and measures the stack by token count. It does not copy their kernel code. Missing signatures are reported and left at the parent choice. The public aggregate score is not evidence of a gain on our implementation.

The H200 public-image driver compares full turn-1 sliding, turn-4 full and first-turn sliding layers, with two input seeds each. It shares prepared weights and other state, checks all outputs against the challenge reference, includes an A/A baseline control and randomizes 16 cold-L2 graph rounds. The SGLang stub, pinned attention and preparation timing differ from the official judge; any promising result requires complete official correctness and scoring. The subprocess is capped at 300 seconds. Selected signatures, raw samples and failures are in `modal.log`.

Run `ap-ZR1DBwe949Kt9ZoOgAQhao` completed with return code 0. Every requested signature was offered and all 18 reference checks passed. Median paired baseline1/candidate ratios for the two seeds were 0.99852 / 0.99849 at 753 tokens, 0.99832 / 0.99733 at 3012 tokens, and 1.00033 / 1.00052 at 16384 tokens. A/A ratios were 1.00204 / 0.99931, 1.00097 / 0.99973, and 0.99965 / 0.99981 respectively. The public plan stack did not show a useful full-layer gain, so retain the current best and do not submit this variant. This comparison does not isolate individual pins or rule out different combinations.
