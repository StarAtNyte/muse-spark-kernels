# Humming routed prefill shape-hint screen

This experiment tests whether Humming's explicit `shape_m` heuristic changes its performance on the same skewed 1,044-route prefill workload as `humming_prefill_stage_profile_v1`. Hints 128, 256, 512, 753, 1044 and 2048 select schedules for both expert GEMMs; actual inputs, expert counts and weights are unchanged. Each candidate is checked against the incumbent's routed expert output and measured in 12 alternating cold-L2 CUDA-graph pairs. The incumbent includes gather and planning, while Humming receives pre-gathered normalized inputs; this favors Humming and is not an official workload or score.

The runner pins Humming commit `948e6fd547e703065be51529ac1db5569256774e`, uses the public challenge image and a 300-second subprocess timeout. Logs include configurations, errors and timings. Passing this screen would still require a legal integrated implementation and complete official correctness and performance validation.

The H200 run completed successfully (`ap-xr18JcyDjITN9uh5fpkHXC`; see `modal.log`). All six configurations produced finite outputs within 0.0046 relative L2 of the incumbent for this one synthetic routed case. Median candidate times for hints 128, 256, 512, 753, 1044 and 2048 were respectively 1301.84, 875.58, 646.56, 553.86, 490.22 and 460.11 µs. Corresponding incumbent medians were 232.90–233.78 µs. The fastest tested hint uses an 80-row WGMMA tile with TMA and warp specialization, but remains about 1.97 times the incumbent latency despite the favorable pre-gathered setup. No change is promoted or submitted; these six heuristic schedules do not rule out other Humming schedules or integrated designs.
