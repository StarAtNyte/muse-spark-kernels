# Independent Forge attention judge

`dev/forgekernel/attention_judge/` contains an independent mathematical page-1 sliding attention judge and generated input groups, including returned mutated K/V caches. The first draft incorrectly rounded queries to FP8 and produced 3.84% relative L2 error; its source and log are retained as `fp8_query_judge.py` and `fp8_query.log`.

The corrected BF16 query path was compared to the challenge reference on H200 for three preliminary cases (batch/length 1/1, 1/8, 2/1): output relative L2 errors were 0.00169, 0.00164 and 0.00165, and the newly written K and V values matched exactly. See `bf16_query.log` and `driver.py`. This is not full coverage or the official challenge tolerance.

The manually supplied judge passed Forge's static validation in run `.artifacts/muse_attention_sliding_261031-164209-d8c3`, but calibration job `1793444260` returned **NO MATCH**: all three verify1 output groups had normalized maximum errors 0.1006–0.1236, exceeding Forge's 0.05 calibration cap. The job process succeeded, but the calibration verdict failed. Full output is `log.txt`.

This exposes a mismatch in evaluation semantics: Forge uses normalized maximum error and a 0.125 FP8 output floor over entire returned caches, while the challenge checks relative L2 on newly written cache entries and output, with a per-case output bound informed by FP8 query error. A follow-up using the challenge's local checker confirmed all three failing verify1 groups pass its dynamic output and cache checks; see `experiments/forge_attention_verify_diagnosis_v1/`. Do not simply relax the cap or accept the generic FP8 cache floor as judge-equivalent. This focused page-1 task cannot replace the official full attention suite. The task's shapes now expose a `tokens` axis to express flattened cache locations.
