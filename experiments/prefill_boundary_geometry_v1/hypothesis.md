# Prefill residual boundary launch geometry

The published first-turn sliding profile attributes 464 µs and 282 µs to two residual-boundary kernels, with 16,384 token rows. The current CUDA implementation uses 512 threads/block, recomputes the first residual stream in the second boundary, and requests two blocks/SM in the mode-2 launch bound. It reads/writes large arrays and performs two reductions per row. Hypothesis: changing threads/block, shared/L1 streaming hints, or mode-2 register/occupancy constraint may improve throughput without changing the computation.

`driver.py` extracts the current boundary body and helper functions, compiles a small independent extension with the same sm_90a and fast-math flags, and measures a paired 512-thread baseline against 256/512/1024-thread, hint, and launch-bound alternatives. Mode 1 and mode 2 are screened separately with cold-L2 graph replays. The 753-token test is exploratory for these two recompute modes: the incumbent uses mode 0 at that size, so a win there does not directly apply. Sample-row checks are a screen; full-layer randomized reference and official evaluation remain required. A component result is not a full-layer result. No submission source is changed.
