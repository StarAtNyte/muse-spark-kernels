# Unweight lossless BF16 compression: applicability screen

[Unweight](https://github.com/cloudflareresearch/unweight-kernels), inspected at commit `db0e6d3d4505cf71379f6b9b4567acf598bc186c` (BSD-3-Clause), separates sign/mantissa from exponent, encodes a 16-value exponent palette and supports Hopper reconstructive matmul that rebuilds BF16 before WGMMA. Its [technical report](https://research.cloudflare.com/nikulin2026/) discusses Huffman storage and palette-based inference. The source repository builds a static CUDA library against a ThunderKittens submodule; it does not expose a ready-made challenge submission or PyTorch binding. Actual kernel portability, shapes and performance are untested here.

Challenge projection `reference.py` generates Gaussian BF16 weights scaled by `1/sqrt(k)`, and rules allow lossless weight repacking during `prepare`; activations must keep the specified BF16 precision. `model.py` draws 500,000 independent CPU Gaussian samples using Python's RNG, rounds float32 to BF16 and counts exponent codes. Its seed-39031 model gives 2.544 bits of exponent entropy, with 0.0078% of values outside its 16 most common exponent codes. One byte for sign/mantissa plus entropy-coded exponents would have an ideal payload of 1.318 bytes/weight; a fixed four-bit exponent index gives 1.5 bytes/weight before metadata or exceptions. The current upstream default tile K is 64; under the independent model, a 64-value tile row has ~0.5% probability of containing an out-of-palette exponent. This simple probability is not a measured codec output size, and ignores metadata, Huffman padding, the verbatim representation and correlations.

This is a CPU distribution model, not the judge's GPU RNG, exact generated weights, model checkpoints, compression benchmark, correctness proof or latency measurement. Our incumbent already uses lossless compressed variants for several shapes, and its M128/M256 pooler uses tuned cuBLASLt. A valid next test needs exact challenge-generated weights, bitwise round-trip across unusual values and held-out weights, prepare-time and memory measurement, and paired cold-L2 comparisons with the scored incumbent. Only then consider adapting or integrating the BSD-licensed source with attribution. No candidate or leaderboard gain is claimed.
