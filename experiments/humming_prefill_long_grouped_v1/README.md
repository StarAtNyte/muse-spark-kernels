# Humming grouped GEMMs on long-prefill expert routes

Earlier `humming_prefill_stage_profile_v1` found Humming's grouped NVFP4 expert GEMMs much slower than the fused prefill MoE component at 753 tokens. That result does not establish performance at 16,384 tokens, where the current best prefill profile spends several milliseconds in experts and the tensor-pipe utilization differs. This experiment uses the current best source (SHA-256 `f1807a75ec056b7f3874d4fce02331ca0043ac38a45af7710a8287a252421a92`), pinned Humming commit `948e6fd547e703065be51529ac1db5569256774e`, and the 23,497-route expert counts observed in the archived reference-checked long sliding case (`prefill_route_padding_v1`).

Humming receives pre-gathered normalized activations and runs two BF16-activation/NVFP4-weight grouped GEMMs with a separate SwiGLU. The parent measurement includes its gather and planning. Both paths use the same actual expert weights and reconstructed route distribution; inputs are synthetic and Humming's routing and normalization are excluded, favoring Humming. Output is compared with the parent's corresponding expert rows, not independently validated against the complete reference. Full-path and individually flushed stage timings use eight cold-L2 graph replays; stage measurements are diagnostic and not additive bounds. This is not a legal integrated submission or official score. The subprocess timeout is 300 seconds; raw logs and failures are in `modal.log`.

Run `ap-6CoS2a4UoyfRrI39q1vV0B` completed with return code 0. The Humming output was finite and 0.00410 relative L2 from the parent's selected expert rows on this synthetic case. The parent including gather/plan measured 2990.86 µs; pre-gathered Humming measured 4573.63 µs. Separately flushed stages measured 2227.42 µs for GEMM1, 1266.93 µs for standalone SwiGLU and 1137.90 µs for GEMM2. Separate captures do not add exactly to the full path, and these timings do not bound a fused or differently tuned design. However, the two standalone GEMM medians together exceed the parent's full component time, so removing activation overhead alone is not a demonstrated win. No kernel is promoted or submitted. Attention validation emitted the known SGLang-stub errors; the expert comparison is independent of attention.
