# Prefill router-first scheduling screen

The scored prefill source runs the router GEMM on a side stream concurrently with the pooler GEMM. Its existing serial path runs the router GEMM first on the main stream, then overlaps top-k with the pooler. The hypothesis is that avoiding concurrent GEMM resource contention could shorten the full-layer critical path despite the additional dependency. This screen changes only the serial dispatch choice while capturing the graph; all inputs, weights, plans and other operations are shared.

The public H200 image driver measures full layers for turn-1 sliding, turn-4 full and first-turn sliding, two seeds each. It checks both variants against the task reference, captures two independent baseline graphs as an A/A control, and runs 16 randomized cold-L2 graph rounds. SGLang is stubbed, attention is pinned, and this is not the official environment; a promising result requires complete official correctness and scoring. The subprocess is capped at 300 seconds. Results and failures are preserved in `modal.log`.

Run `ap-BLsFSciigNN1jdCcuFi135` completed successfully and all 18 reference checks passed. Median paired baseline1/serial ratios were 0.9976 / 0.9985 for turn-1 sliding, 1.0020 / 1.0000 for turn-4 full, and 0.9983 / 0.9992 for first-turn sliding. The corresponding A/A ratios were 0.9991 / 1.0015, 1.0017 / 1.0014, and 1.0003 / 1.0005. These small mixed differences do not establish a useful improvement; retain the scored concurrent schedule and do not submit this variant. The results do not rule out other overlap strategies.
