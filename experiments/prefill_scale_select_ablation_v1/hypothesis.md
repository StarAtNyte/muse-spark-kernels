# Prefill repeated-scale selection ablation

Potential K64 permutation would allow a lane to reuse its original scale block across four k16 steps. This screen substitutes `scale_pair_sel(t < 2 ? sc.x : sc.y, t & 1, m16)` for the four existing selection sites without permuting weights or activations. Outputs are intentionally invalid. It is an instruction-scheduling probe, not a valid kernel, correctness test, speedup claim or strict upper bound: the compiler can hoist or duplicate the dynamic selection, and a real permutation would add packing, activation shuffle, altered intermediate publication and possible register pressure. Parent source SHA-256 `9a12398e9db70abb59ee3a914e185a5e8010e2557056ece22528f6b0b8c24217`; driver SHA-256 `a9a46e99ed711ccd21cba6b2fb8a7ae0ef44d574030e1b3e87304d55a2503476`. Public-image app `ap-hnwcq3lXlQs8DqxTY2Fart`, 300-second subprocess cap. It uses the existing whole-layer ablation harness, with paired cold-L2 graph timing and pinned attention, and retains the captured outputs. The harness stubs SGLang, so it is not an official judge replica.

Result: completed with intentionally invalid outputs. Paired median ratios were 1.0074× (turn 1 sliding), 1.0015× (turn 4 full), 0.9986× (first turn ctx0) and 1.0165× (first turn ctx65536). The parent and ablation independently tuned cuBLASLt and selected different T=16384 router choices; the SGLang attention stub also caused validation/tuning errors before attention was pinned. Thus the whole-layer ratios cannot isolate the scale change, especially at 16K tokens. There was no reference check or direct WGMMA fragment validation. This is neither a validated optimization nor a hard upper bound; do not promote. A useful next test must use the same tuned plans in both arms, inspect generated SASS for hoisting, and validate the real permutation with matching activation and intermediate layouts.
