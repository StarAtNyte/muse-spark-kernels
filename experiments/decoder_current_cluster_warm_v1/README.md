# Transfer attention cluster-epilogue warming into current decoder

The current standalone attention winner uses an out-of-line, dry cluster-epilogue call to warm instruction cache while initial data loads are in flight. The current best decoder embeds an earlier attention implementation. This candidate adapts that technique to the decoder's cluster epilogue, retaining its existing debug code and making the dry call skip cluster synchronization, remote/shared reads and output writes. The CUDA extension gets a distinct module name so parent and candidate do not accidentally share the same compiled binary. Parent source is `decode_keell0renz_compare_v1/submission.py` (SHA-256 `82c098ae7534b20b5d80f59d547650cb0853fc7d5e313fe29e1e9d9373e1bb19`).

The first public-image H200 screen isolates the decoder's actual `_launch7` attention path and checks it against the attention task reference for sliding batch 1/16/32, query lengths 1/8 and two seeds. It uses alternating cold-L2 graph timings and distinct compiled modules. This is not a full decoder test or proof of synchronization safety, and SGLang is stubbed. A promising result requires review, whole-decoder paired tests and complete official correctness and scoring. The subprocess is capped at 300 seconds; source, driver, timings and failures are preserved here.

Initial public-image run `ap-LPJIpvSwmacgLnxSgnjYgN` completed with return code 0 and all 24 attention reference checks passed. Median paired parent/candidate ratios for seeds 419 / 7919 were 1.0084 / 1.0275 at sliding decode batch 1 and 1.0069 / 1.0178 at batch 16. Other shapes were mixed and within about 2%; these timings include graph/event overhead and no A/A control. This is only an isolated component lead, so test the exact change in the full decoder before spending an official check. The dry path still needs careful synchronization review and full challenge correctness.
