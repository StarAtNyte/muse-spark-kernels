# MoE KPERM3 activation gather with L1 bypass

The scored parent (`experiments/scored_moe_ours_kperm3_v1/submission.py`, SHA-256 `ac008155520981cd67928bd52bb647efa64096add5acc8edabc779261105792f`) gathers permuted activation words using `__ldg`. This experiment substitutes four inline PTX `ld.global.cg.u32` loads at that gather site, bypassing L1. The hypothesis is that routing these loads through L2 could reduce L1 contention in the WGS path; the cache policy also changes latency and the source uses volatile inline assembly, so a regression is plausible. This does not change routing, arithmetic or weight format.

The public-image H200 driver uses normal dispatch and shared prepared weights, reference-checks parent and candidate, and alternates 16 cold-L2 CUDA-graph measurements at batches 32, 128 and 256 with two seeds. It is a component screen, not the official harness. Any apparent gain needs full official correctness and score validation. The runner caps the subprocess at 300 seconds; `modal.log` retains output.

The run `ap-Nr4Se6pv59VemXsP6loYjL` completed with return code 0. Both arms passed the task reference for all six cases and produced identical outputs in this screen. Median paired parent/candidate ratios were 1.0019 and 1.0055 at batch 32, 1.0042 and 1.0076 at batch 128, and 0.9952 and 1.0035 at batch 256 (seeds 419 and 7919 respectively). These small and mixed changes do not establish a useful improvement; the scored parent remains unchanged and this candidate is not submitted. The test does not isolate cache effects from the changed instruction sequence or rule out a different memory design.
