# Single-token pooler geometry screen

The current best projection source uses a losslessly packed v18 single-token pooler, with work geometry `(WR, WK, KU, S) = (2,16,8,1)`. This H200 screen preserves the lossless format and mathematical operation but tests `(2,8,8,2)`, `(2,8,16,1)`, `(1,16,8,1)`, and `(2,16,4,2)` as alternative work partitions. Split-K cases use cluster reduction and may change floating-point reduction order. Each candidate repacks weights for its geometry and is checked against the task reference for two input seeds; 24 randomized cold-L2 graph rounds compare it with the complete scored dispatch.

The public challenge image uses an SGLang stub; the component harness and direct candidate wrapper are not the official judge. The screening code verifies exact pack/unpack and checks output but does not perform the full one-hot, all-shape, or concurrency validation required for promotion. Any lead needs stronger matched-dispatch tests and official checks. Subprocess timeout is 300 seconds; plans, failures and timings are in `modal.log`.

The first run (`initial_failure.log`) stopped at a launch error `-9`: the split-K geometry required cluster reduction, which the initial driver had not enabled. The corrected run `ap-dyTkF5SP6y23cv2dzBqVK2` enabled reduction for `S > 1`, completed with return code 0, and passed the reference for both seeds on all four candidates. Median paired baseline/candidate ratios for the listed geometries were 0.9428 / 0.9459, 0.9635 / 0.9587, 1.0033 / 1.0066, and 0.8598 / 0.8569 respectively. The third geometry is too close to noisy timing and uses a different direct wrapper, so no reliable improvement is established. Keep the scored baseline and do not submit; raw samples and the original failed run are retained.
