# Humming long-prefill shape-specific schedules

After `humming_prefill_long_activation_v1` reduced the standalone activation overhead with Humming's compiled BF16 SwiGLU, the resulting pre-gathered grouped path still trailed the current fused expert component by about 15.5%. This experiment asks whether explicitly selecting heuristic schedules for 16,384, 23,497 or 32,768 rows improves the same 23,497-route workload. The hint changes only schedule selection; actual inputs and expert counts stay fixed.

The public H200 image uses the exact current best prefill source and pinned Humming checkout. Each candidate is compared with the parent's corresponding expert rows and measured in eight alternating cold-L2 CUDA graph pairs. Humming receives pre-gathered normalized inputs, while the parent includes gather and planning; it is a favorable component diagnostic, not a legal submission or official score. A promising result needs integrated routing and full correctness and scoring. The subprocess is capped at 300 seconds; logs and configs are in `modal.log`.

Run `ap-E1nAbs8gJWNMTBdGZHlhnO` completed successfully. All three outputs were finite and within 0.00411 relative L2 of the parent expert rows. For hints 16384, 23497 and 32768, candidate medians were 3685.97, 3541.18 and 3507.73 µs respectively; paired parent medians were about 3056 µs. Thus all tested schedules remained slower despite excluding Humming's gather and normalization. Do not promote or submit this path. These are single-workload component measurements and do not rule out other schedules or genuinely fused designs.
