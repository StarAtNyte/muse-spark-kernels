# Prefill MoE scale reuse: transfer hypothesis

KPERM3 rearranges NVFP4 codes and corresponding BF16 activations, once per prepared weight and during the timed gather, so four inner steps reuse the same scale pair. Decoder/standalone MoE WGS uses 256-element K stages and a different activation layout. Prefill uses 64-element stages, 128-row weight tiles (`WBLK=4608`), a swizzled BF16 shared-memory operand, and `convert8` for four k16 operations per stage. Its packer `_repack`, activation gather, `moe_fused_persistent` WGMMA descriptors, gate/up interleaving and down-projection ordering must all agree on any K permutation. Reusing the existing KPERM3 code without remapping these would silently produce wrong outputs.

Hypothesis: an invertible in-stage K permutation that keeps a lane's scale identity fixed across multiple producer groups could reduce scale decoding/loads, provided both packed codes and activation operands are permuted consistently and the phase-A output order matches phase-B input order. For each 64-element stage, derive and verify bijection of 64 indices, exact association of every FP4 nibble with its original 16-element scale block, preservation of gate/up pair ordering, and consistency of input/output permutations. Test arbitrary normal, zero, subnormal, negative and NaN-capable scale encodings through both fast and fallback paths; no numerical precision change is allowed. This is a proposed design, not implemented or validated.

Impact bound from existing whole-layer invalid-output ablation: removing all four scale multiplies produced 1.036× turn-1 sliding, 1.024× turn-4 full, and 1.002×/0.991× on long full cases (`experiments/prefill_hmul_ablation_v1/`). The modified layout could also alter loads or register pressure, so that ablation is directional, not a strict ceiling. NCU measured 92.6% SM throughput and 10.5% DRAM on one long case (`experiments/prefill_moe_ncu_v1/`); prioritize the short-turn shapes first, and preserve the unmodified long route until a paired complete-layer screen demonstrates otherwise.

Attention has input-dependent FP8 KV caches and no untimed weight preparation: persisting an input-dependent reordered cache outside the timed call is not allowed. Test producer locality and reuse within a call rather than importing MoE's prepare-time permutation. Projection weights do permit lossless prepacking; our existing compressed and shape-specific routes already exploit it, so new layout proposals should target measured per-shape DRAM traffic and include one-hot precision checks. See `research/H200-LOWER-BOUNDS.md` for the models and `kernels/*/AGENTS.md` for current task constraints.

## Abstract 64-element mapping (2026-10-30)

For a permuted stage position `p = 16*j + c`, where `j in [0,3]` and `c in [0,15]`, define `t=(c>>1)&3`, `i=(c&1)|((c>>3)<<1)` and `k=16*t+4*j+i`. The exhaustive CPU verifier `derive_permutation.py` proves this is a bijection on 0..63, verifies `floor(k/16)=t` is constant across the four `j` values for a fixed `c`, and checks an exact rational dot product under consistent weight and activation permutation. Raw output: `permutation.log`.

This only establishes an algebraic candidate: the real RS-WGMMA lane-to-fragment mapping, packed BF16 activation addressing and gate/up-to-down channel permutations have not been matched or implemented. Floating-point reduction order, special scales, barriers and GPU correctness remain unverified. No speedup or viable kernel is claimed. The current prefill consumer loads one 8-byte scale group per lane group (`g`) and selects two bytes for each `j`; a real implementation would trade that broadcast for lane-dependent scale addressing. Measure actual instruction count, coalescing and whole-layer performance before concluding this improves anything.
