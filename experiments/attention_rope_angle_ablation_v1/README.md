# Sliding attention RoPE-angle ablation

The scored kernel computes range-reduced sin/cos values within each attention CTA. This diagnostic replaces the only `__sincosf(rr, &sv, &cv)` call with `sv=0; cv=1`, leaving the rest of the kernel intact. **The ablated outputs are invalid**: this is solely an exploratory measurement of the angle-computation path, not a candidate or a correctness claim. Compiler dead-code elimination and changed scheduling can affect other instructions, so the observed difference is not a strict bound on the benefit of a correct shared-angle implementation.

The public-image H200 driver reference-checks the baseline and compares it with the invalid ablation for six sliding shapes (batch 1/16/32, query length 1/8), one seed and 24 alternating cold-L2 graph replays. See `modal.log`; the subprocess timeout is 300 seconds. A useful signal would motivate a correct implementation, followed by full verification and end-to-end measurements.

Run `ap-D61PT4rq60u3J3jqpUymGo` completed with return code 0. All six baseline reference checks passed. Parent/invalid-ablation ratios, based on the separate timing medians, were 1.000 and 1.016 for batch 1 query lengths 1/8; 0.998 and 1.008 for batch 16; and 0.994 and 1.001 for batch 32. The largest apparent saving was about 0.18 µs in the batch-1 verify case, on one seed. Most cases show no useful signal and the diagnostic changes compiler output, so do not infer a hard limit or promote this invalid ablation. A separate angle-precompute launch is not currently supported by this evidence; focus on other sources of latency.
